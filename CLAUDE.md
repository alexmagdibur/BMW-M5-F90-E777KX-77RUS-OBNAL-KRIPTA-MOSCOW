# ZOV AUTO: МОЖНО, А ЗАЧЕМ

Консольный Java-симулятор управления гоночной командой. Учебный проект МГТУ им. Баумана, курс «Технология программирования», ЛР1–ЛР3.

## Суть игры

Игрок — директор гоночной команды. Покупает компоненты, собирает болид, нанимает пилота и инженера, участвует в гонках. Зарабатывает призовые, управляет износом и рисками. Есть режим выживания с оружием.

## Стек

- **Java 17**, Maven
- **JUnit 5.10** — тесты
- Сборка: `mvn test` из `src/`
- Точка входа: `src/game/app/Main.java`
- Исходники: `src/game/` (Maven sourceDirectory = `game`)
- Тесты: `src/test/`

## Структура пакетов

```
src/game/
├── app/        — Main.java (точка входа)
├── domain/     — сущности: Bolid, Component, Pilot, Engineer, Team, Track, Weather, Race, Weapon...
├── service/    — бизнес-логика: RaceService, ShopService, AssemblyService, WearService, WerewolfService, SurvivalRaceService...
├── data/       — статические каталоги: ComponentCatalog, PilotCatalog, EngineerCatalog, TrackCatalog, WeaponCatalog
├── saving/     — сохранение/загрузка: SaveFileManager, SaveService, GameSave, BolidBinarySerializer, BolidReportWriter, TrackFileManager
├── ui/         — консольный UI: GameMenu, ConsoleInput, TrackEditor
└── util/       — RandomUtil, Ansi (ANSI-форматирование консоли)

src/test/       — JUnit-тесты (28 файлов)
saves/          — папка с сохранениями (создаётся при первом запуске)
```

## Что реализовано (все три лабораторные)

### ЛР1 — Основная игра
- Команда с бюджетом (стартовый бюджет 10 000 000 руб.)
- Магазин компонентов (6 типов: двигатель, трансмиссия, подвеска, шасси, аэропакет, шины) + экстра
- Сборка болида с проверкой совместимости компонентов
- Набор экстренной помощи (аптечка, огнетушитель, знак) — обязателен для старта гонки
- Найм пилотов и инженеров
- Гонка: расчёт времени через `RaceCalculator`, боты, рейтинг, призовые (1-е: 2M, 2-е: 1M, 3-е: 500K)
- Погода: Солнечно / Влажность / Дождь / Солнечное затмение (разные множители для секций трассы)
- Износ компонентов после гонки, предупреждения, ремонт/замена через инженера
- Инциденты при 100% износе (DNF)
- Оборотни: при солнечном затмении пилот/инженер могут обратиться → DNF. Охотник (Ван Хельсинг) убивает, Баффи лечит
- Трассы из секций (STRAIGHT / TURN / CLIMB / DESCENT), редактор кастомных трасс

### ЛР2 — Сохранение и сериализация
- Сохранение/загрузка игры в CSV (`saves/{имя}/save_*.csv`)
- Автосохранение после каждой гонки (`autosave.csv`)
- Бинарная сериализация болида (`*.bin`) — через `BolidBinarySerializer`
- Экспорт отчёта болида в JSON — через `BolidReportWriter`
- Сохранение/загрузка кастомных трасс — через `TrackFileManager`
- `EntitySerializer` — сериализация/десериализация отдельных сущностей (Component, Pilot, Engineer)

### ЛР3 — Режим выживания
- Пошаговая гонка на выбывание (`SurvivalRaceService`, `SurvivalRaceState`)
- Оружие двух типов: ближний бой (MELEE) и дальний (RANGED), уровни 1–3
- Ограничение совместимости: уровни 1 и 3 несовместимы между собой
- Действия за ход: обгон / атака ближним / атака дальним / пропустить
- Боты случайно атакуют других участников
- Покупка оружия из каталога (`WeaponCatalog`) и установка в болид перед гонкой

## Архитектурные правила

- **domain** не знает о service и ui — чистые данные + поведение сущности
- **service** знает о domain, не знает о ui
- **ui** вызывает только сервисы, не считает формулы
- Все поля `private`, доступ через геттеры/сеттеры
- `toString()` переопределён у всех доменных классов
- `TeamMember` — абстрактный базовый класс для `Pilot` и `Engineer`

## Ключевые классы

| Класс | Роль |
|-------|------|
| `Main` | Точка входа, выбор/загрузка сохранения, запуск меню |
| `GameMenu` | Главное меню (15–16 пунктов), оркестрирует все сервисы |
| `RaceCalculator` | Формула времени: болид × пилот × инженер × секции трассы × погода |
| `RaceService` | Запуск гонки, оборотни, инциденты, призовые |
| `SurvivalRaceService` | Пошаговая гонка: обгон, атаки, выбывание |
| `SaveService` | Сохранение/загрузка через CSV |
| `WerewolfService` | Ван Хельсинг / Баффи: обнаружение и устранение оборотней |
| `WearService` | Применение износа после гонки, стоимость ремонта |
| `AssemblyService` | Сборка болида с проверкой совместимости и набора экстренной помощи |
| `BotGenerator` | Генерация бот-команд и их результатов |
| `TrackEditor` | Консольный редактор кастомных трасс с сохранением в CSV |

## Запуск

```bash
cd src
mvn test          # запустить тесты
mvn package       # собрать jar
java -cp target/classes app.Main   # запустить игру
```

Либо через IntelliJ IDEA: открыть `src/pom.xml` как Maven-проект, запустить `app.Main`.

## Сохранения

Папка `saves/{имя команды}/`:
- `autosave.csv` — автосохранение (перезаписывается после каждой гонки)
- `save_DD-MM-YYYY_HH-mm-ss.csv` — ручные сохранения
- `bolid_{имя}_{дата}.bin` — бинарные дампы болидов
- `bolid_{имя}_{дата}.json` — JSON-отчёты болидов
- `tracks_{имя}.csv` — кастомные трассы

## Тесты

28 JUnit-тестов в `src/test/`. Покрывают: гонку, износ, инциденты, оборотней, сохранения, сериализацию, режим выживания, оружие, редактор трасс, совместимость компонентов.

`RaceService` имеет конструктор без параметров (для тестов) и статический метод `setWerewolfChance(double)` для управления вероятностью оборотня в тестах.

## Контекст ЛР

- **ЛР1**: базовая игра (все 25 обязательных требований методички + допзадание с оборотнями)
- **ЛР2**: сохранение состояния, бинарная и текстовая сериализация, редактор треков
- **ЛР3**: режим выживания с боевой механикой и оружием
